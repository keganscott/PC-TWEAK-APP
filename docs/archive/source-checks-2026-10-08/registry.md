# VERIFY check: registry values a tool writes (primary sources only)

Checked 2026-10-08 against Microsoft's own documentation, using learn.microsoft.com (WebFetch), support.microsoft.com and the MicrosoftDocs Markdown sources on raw.githubusercontent.com. Microsoft Q&A threads (learn.microsoft.com/answers) were not counted, nor were blogs, forums or tweak sites. Paths are relative to `crates/engine/src/tweaks/` unless a path is given. Verdicts: CONFIRMED means the quote states the claim. PARTLY means some of the claim is stated and the rest is not. CONTRADICTED means the source says something different. NOT FOUND means no primary source was found.

Two limits on what could be read:
- The large Policy CSP pages (Privacy, System) are longer than the fetch tool returns: about 112 KB of the page is read. I could not read the Privacy CSP rows for PublishUserActivities and UploadUserActivities.
- The "Manage connections from Windows ... to Microsoft services" page could be read only through section 18.8. Section 18.17 (Background apps) and 18.22 (Activity History) were not reached.

## Other findings from the same sources (not claims in the code, but relevant to it)

- **Activity history (registry_values.rs:514-527).** Microsoft says turning these policies off stops Windows settings backup: "These policies must not be set to Disabled. If any of these policies are disabled, Windows Backup will not occur." (https://learn.microsoft.com/en-us/windows/configuration/windows-backup/). The tool's trade-off text does not say this.
- **Games task (registry_values.rs:444-459).** With Microsoft's MMCSS rules, only `Scheduling Category = High` changes anything: `Priority` 6 is treated as 2 under High, and `SFIO Priority` is "not used". The card text "Raises the priority ..." is still true through the category alone.
- **Timer (registry_values.rs:651-663).** Windows 10 version 2004 introduced the per-process behaviour, so a Windows 10 2004+ PC is in the same position as Windows 11 per Microsoft. The summary "as before Windows 11" and the comment "restores the system-wide behaviour of Windows 10" are wrong for Windows 10 2004 and later.
- **Optimizations for windowed games.** The support page says that turning on Auto HDR turns this setting on, and that Auto HDR must be turned off before this setting can be turned off. Undo may not take effect while Auto HDR is on.
- **csrss (H3).** Microsoft: "Starting in Windows 10, CSRSS is a protected process and can only be debugged in kernel mode." No Microsoft source says IFEO PerfOptions applies to it.
- **RSS change and the connection (NOTES N90).** For per-adapter RSS (`Enable-NetAdapterRss`), Microsoft says the change "causes temporary connectivity loss for about one minute" (https://raw.githubusercontent.com/MicrosoftDocs/azure-docs/main/articles/virtual-network/virtual-network-optimize-network-bandwidth.md, Azure Windows VM context). Nothing was found about the global `netsh ... rss=` switch.
- **TcpAckFrequency.** KB 328890's "appliesto" field lists Windows Server only. It is the only Microsoft source for the value.
- **Advertising ID.** Microsoft's documented location is HKLM. Microsoft documents no per-user (HKCU) value for the Settings switch.
